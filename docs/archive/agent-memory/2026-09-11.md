### Stage 1 — Qwen parser fix (commits `7620342`, `1bb609c`, `e27ffb5`)
Root causes discovered via API tests on fan-dragon:
1. **Qwen3 emits unclosed `<tool_call>` tags** → regex `<tool_call>...</tool_call>` misses → 0 tool calls executed
2. **Qwen3 leaks CoT into visible reply** ("We need answer user asks..." preamble) → ugly UX
3. **ModelManager vs global engine wedge**: `data_prep_chat.py` calls `mgr.load(provider_id)` which fails when global engine already holds the model

Fixes:
- `_extract_tool_calls()` now (a) strips `` blocks first, (b) falls back to brace-balanced extraction for unclosed tags
- `_strip_thinking_reply()` strips CoT from visible reply
- `SYSTEM_PROMPT` rewritten to be directive: explicit closed `<tool_call>...</tool_call>` examples, no CoT, always close tags
- Global-engine fast path in `data_prep_chat.py`: if global engine holds same model, skip `mgr.load()` and call `engine.model.create_chat_completion()` directly
- ModuleNotFoundError fix: `from finetune_studio.webui.app import inference_engine` (singleton, not `get_engine()` from `models.inference`)
