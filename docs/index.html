⚡ FINETUNE STUDIO▮

Train, run, and evaluate large language models — entirely on your own hardware.

A self-hosted workshop for the whole lifecycle: documents → datasets → LoRA training → merge/export → offline benchmarks → chat. One dark-themed WebUI that lives in your browser. No cloud, no telemetry, no lock-in.

FOUR USE CASES

You don't have to use everything. Pick what you need — most users start with one and grow.

1 · RAG ON PRIVATE DOCUMENTS

"I have a pile of PDFs and want to ask questions about them in plain English — without uploading anything to the cloud."

File ingestion (PDF, DOCX, TXT, MD, HTML, code, CSV, JSON, images via OCR). Configurable chunking. Embedder model selection. Live build progress via SSE. Documents-indexed panel with per-doc Rebuild + View-chunks modal.

RAGVECTOR SEARCH

2 · FINE-TUNE A MODEL

"I want to teach a small open model how my company talks."

Point at a JSONL or your mined dataset, pick a base model, run LoRA / QLoRA. Live loss curves, VRAM profiles, adapter merge, then export (merged / abliterated; GGUF and GPTQ when host tools are installed). Per past-run Actions (⭐ Set Production, ▶ Inference, ⬇ Download).

LoRAQLoRAMERGEEXPORT

3 · BENCHMARK BEFORE SHIP

"I trained two variants. Which one is actually better?"

Offline smoke suites styled after MMLU / GSM8K / HellaSwag (not the full HuggingFace dataset downloads), plus project-local suites. Two tabs: Recent scores and Compare two runs (per-suite Δ = B − A, colored).

MMLU-styleGSM8K-styleHellaSwag-style

4 · JUST CHAT LOCALLY

"I want to run Llama 3 locally with my own chat history and image support."

Pick a safetensors or GGUF model, load with auto-unload-on-idle to free VRAM. Image input for multimodal. Per-session temperature / top-p / system prompt. Conversation persists.

THE PIPELINE

From raw documents to a benchmarked, chat-ready model — one project, one flow:

upload ──► file library      sha256 dedup · MIME auto-folders · versioning · 7-day trash · rename · per-file purge · parsed MD
   └─► parse + chunk      pdf · docx · csv · xml · images(OCR) ── ~500-token chunks
        └─► corpus            PortableRAG parquet + sources + live SSE
             └─► Q&A mining      batch prep job  OR  agentic tool-calling chat
                  └─► review           approve / reject / edit pairs ──► JSONL datasets
                       └─► train           LoRA / QLoRA / full · live loss · VRAM profiles · per-run Actions
                            └─► merge + export adapter → merged → optional GGUF/GPTQ when tools installed
                                 └─► benchmark     offline smoke suites · compare tab (Δ = B − A, colored)
                                      └─► chat          single-model engine · vision · RAG context · log tail

WHY THIS OVER DOING IT MANUALLY?

None of the pieces are impossible by hand. The point is that all of them are now in one place, with your data in ~/.finetune-studio/ where you can find it.

What you'd do manuallyWhat Finetune Studio does
Five terminal windows + a Notion page of "things to remember"One browser tab, one project concept
Hand-craft chunking + embedding loopsClick Build — SSE progress the whole way
Write your own eval harnessPick a suite, click Run, get a comparison table
Lose an afternoon to CUDA install issuesOne ./install.sh — GPU-aware wheels, self-repair
Guess why a model will not loadSee estimated VRAM needed, free VRAM, and the named GPU processes using it
Compare two trained runs by handCompare tab — pick run A + B, get the Δ table
SSH in to grep server logsSettings → WebUI log tail, Refresh + Auto-refresh

QUICKSTART

Linux / macOS / Windows(WSL2). Auto-detects your GPU and picks the right CUDA wheels.

$ git clone https://github.com/GenorTG/finetune-studio.git
$ cd finetune-studio
$ ./install.sh                    # GPU detection, venv, wheels
$ source .venv/bin/activate
$ fts web --host 0.0.0.0 --port 7860
# open http://localhost:7860 — an 8-step tour walks you through it
