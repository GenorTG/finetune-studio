## Purpose
The main path of a project, step 2. The Smart Brain answers from the project's files: it finds the passages that answer a question and the model quotes them, so answers cite their source and new or edited files only need a rebuild. Minutes, not hours; model weights never change. It reads the same parse training uses (Files & Knowledge), including Vision-reader readings and hand edits. Methods: semantic search (embeddings) + keyword search (BM25), combined by rank fusion, then reranking (cross-encoder); an answer gate declines when nothing found covers the question. Often called RAG.

## Workflow
1. Add files: drop them on this page (**＋ Add files**) or use Files & Knowledge; each readable file is parsed on arrival.
2. Click **Build Smart Brain** (**Update Smart Brain** after files change): it parses any file that is not parsed yet and builds the index from the files' passages, the same ones mining reads (first run downloads the embedder, ~2.2 GB).
While it builds, the bar shows the passages embedded, the time taken and the time left; **Stop build** ends it and keeps the old index. A large embedder (e5-large, bge-large, Qwen3-Embedding) on the CPU can take many minutes.
3. The panel at the top says the state in words: *Ready*, *Needs an update* (files changed since the build, new files, removed files), or what is still missing.
4. **Test a search** (under Manage): ask a fact question per document type; the top hit must be the right passage and show its source filename and score.
5. **Ask your documents** to chat with sources; follow-up questions keep the conversation, and **New conversation** clears it. Each answer lists the files it used: open one to read the passages. With no chat model loaded, load one in the same panel. When a question reaches its answer through another item ("who manages the site where pump X is installed?": the first search finds the pump's site, never that site's manager), the model may ask for one follow-up search before answering; the chat shows it as *Also searched*. On the Quillmoor benchmark this lifted two-step questions from 10 % to 84 % with the API model and the default reranker.
6. Build it before exporting a dataset if you want retrieved-context rows in the training data.
7. **Studio to studio**: *Build the package* writes an encrypted `.ftsrag` bundle (passphrase shown once); the other studio opens **Import an index from another studio**, picks the file and types the passphrase. The imported index says where it came from; a rebuild there indexes that project's own files instead. CLI: `fts brain bundle` / `fts brain import`.
8. **Standalone server export**: pick the search layers it ships, each a separate switch. **Meaning search** (vectors: finds passages that say the same in other words; needs the embedder inside via *Include models*, or an embeddings API where it runs), **Word search** (BM25 keyword index: exact names, codes, numbers; no model), **Rank fusion** (RRF; automatic when both searches are on), **Reranker** (a cross-encoder rescoring pass; needs *Include models*) and **Answer generation**, the "G" in RAG (the server also writes the answer with any OpenAI-compatible chat model: endpoint and model name here, the API key only where it runs; a preset fills OpenAI, Claude, OpenRouter or a local server, Claude uses its own Messages API). The running package also serves a **chat page** at `http://127.0.0.1:<port>/` (pick OpenAI, Claude or any OpenAI-compatible API and type a key; the key stays in the browser) and **MCP over HTTP** at `/mcp` for remote MCP clients (`claude mcp add --transport http <name> http://127.0.0.1:<port>/mcp`; set `RAG_AUTH_TOKEN` and HTTPS beyond this machine). Local MCP clients (Claude Code, Codex, Cursor, Claude Desktop) start `server.py --mcp` instead; the README has the snippets. Before the download is offered the package opens itself: every shipped search layer runs a real search (meaning search with the studio's embedder if the package carries none), then its chat page and `/mcp` must answer. The **Pipeline** line shows how a question travels through the package; the package ships only the files its layers use. The same switches exist as `fts brain export --no-semantic/--no-keyword/--no-reranker/--answer`.

## Key controls
- `#brain-hero` — the current state and the one next action.
- `#brain-lint` — Knowledge check: errors (unreadable files, real keys) and items to review (almost no text, garbled, duplicates, out-of-date versions, documents that disagree on a value, possible passwords, index out of date). Review items can be ignored; the check needs no model. Conflict detection needs a built index. An amendment ("Amendment No. 1", naming the agreement's reference) is linked to the agreement it amends and reported as **amended: check the amendment's terms are used** (not as a duplicate or a conflict); a workbook that keeps last year's sheet next to this year's ("Bands 2024" / "Bands 2025", or a sheet titled "superseded") is reported as an older sheet; `salary_bands_2024` next to `salary_bands_2025` is an out-of-date version; a lone `…_DRAFT` file with nothing newer is shown as a draft (information, nothing to fix). Exports refuse out-of-date versions nobody accepted, on the page and in `fts brain export` (`--accept-superseded` packages them anyway). It also reports pictures (charts, table images, scanned pages) that only OCR read: "N pictures read by OCR only — figures in charts may be wrong; set a vision reader", with a link to Settings → AI assistant → Reading pictures.
- `#lint-read-pictures` — Read pictures: the vision reader reads every chart, table image and scanned page that only OCR read, then the files' text is updated (Update Smart Brain uses it). With a vision reader set this runs by itself when files arrive; a mined file keeps its OCR text (Reset it in Mining first). `#lint-pictures` shows how many pictures each reader read. CLI: `fts brain pictures --project P [--read --wait]`. Native Office charts (xlsx, pptx, docx) need no reader: their series and values are read from the chart data.
- `#brain-identity` — who it speaks for: name, about you or your company, personality and how to answer. Used in every answer and in Testing and packed into the export (MCP `rag_profile`, HTTP `/profile`). Facts still come only from it and the files; no rebuild needed.
- `#quick-index-btn` — Build / Update Smart Brain: one-click parse + build.
- `#brain-add-files-btn` — add files without leaving the page (`#brain-upload-input`).
- `#chat-new-btn` — start a new conversation.
- `#chat-retry-missing` — Search again for a missing part (on by default): when an answer says part of the question is not stated, the chat searches once more for just that part and writes the answer again; it says what it searched and which files it added. One retry per answer. Packages do the same (`/ask`, `rag_answer`; the reply's `followup`; `RAG_RETRY_MISSING=0` turns it off). CLI: `fts brain ask --no-retry-missing`.
- `#chat-model-select` — pick a local model to answer with when none is loaded.
- `#s-max-per-doc` — Per document (retrieval settings): at most this many passages of one document in a search's top results before other documents get a turn (default 3; 0 = no cap); its other passages still fill the end when nothing else matches. Studio search, chat and exported packages use it (a package server can override it with `max_per_document` / `RAG_MAX_PER_DOCUMENT`).
- `#b-embedder` — embedding model (multilingual-e5-large default; bge-large-en for English-only; all-MiniLM-L6-v2 is small and weaker).
- `#build-btn` (under **Build options**) — build; `#rebuild-btn` wipes and rebuilds from scratch.
- `#build-stop-btn` — stop a running build; it ends after the current batch and the old index stays as it was.
- `#reembed-btn` — after changing the embedder: keep the passages, replace only their vectors (quicker than a rebuild; needs an index).
- `#b-fact-cards` — also index approved Q&A pairs as fact cards (off by default).
- `#s-reranker` — the reranker model. A new index gets **bge-reranker-v2-m3** on a machine with a GPU (multilingual, most accurate: on the Quillmoor benchmark it found the right passage in the top 5 for 89 % of questions against 79 % for MiniLM, at about 0.2 s per search) and **ms-marco-MiniLM-L-6-v2** without one (small and fast on a CPU, English). Changing it applies to the next search; no rebuild needed.
- `#s-rerank-enabled` — reranking on/off.
- `#s-hybrid-enabled` — keyword search + rank fusion on/off (off = semantic search only).
- `#s-rerank-top-n` — how many candidates to rerank (default 50).
- `#q-text` — Test a search box.
- `#brain-chat` — grounded chat section.
- `#chat-answer-with` — who writes the chat's answer: **the loaded chat model** (top-bar pill) or **the AI assistant**: the API connection of its *Smart Brain chat* job (Settings → AI assistant), so grounded chat works without loading a local model, e.g. to compare the local answer against an outside provider or on a machine without a GPU. The default is always the local model; the AI assistant is never picked for you, even when no model is loaded (the page then says: load a model in Inference, or choose the AI assistant). Choosing it sends your question and the retrieved passages to that provider. On the Quillmoor benchmark the API model with follow-up search scored 96.1 %.
- `#chat-follow-up` — lets the model ask for one follow-up search before answering (on by default). Measured gain with models that follow the instruction (API model 88.4 → 96.1 %, Qwen 3.5 4B 88.8 → 91.1 %); none with Llama 3.2 3B or Gemma 3 4B, and Gemma abstained less, so turn it off for small models that over-use it.
- `#brain-import-panel` — import an encrypted `.ftsrag` bundle from another studio (works in a new project with no index), or **open an exported package** (`.tar.gz` / `.zip` + passphrase) to edit it: its index becomes the project's, its original files (when it ships them) return to Files in their folders, and the next export can be a new version of it. CLI: `fts brain import --project P package.tar.gz --passphrase-file F`.
- `#mcp-layers` — standalone export: the search layers, one switch each.
- `#mcp-sem` — export meaning search (vectors).
- `#mcp-kw` — export word search (BM25).
- `#mcp-rerank` — export the reranker (needs Include models).
- `#mcp-answer` — answer generation (the "G" in RAG) with an LLM endpoint.
- `#mcp-llm-preset` — fills the answer endpoint and API kind for OpenAI, Claude, OpenRouter or a local server.
- `#mcp-pipeline` — how a question travels through the package.
- `#mcp-scope` — Documents in the package: **All documents** (default) or **Only these** — folders (with their document counts), file tags and single documents. A document goes in when it matches any choice. The package then holds only those documents' passages, vectors, a word index recomputed over them and their files: nothing else can be found or read through it. Use it for a public chatbot from the `public/` folder next to an internal assistant with everything. CLI: `fts brain export --include public/ [--exclude PREFIX] [--tag TAG]`.
- `#mcp-scope-summary` — how many of the index's documents go in ("12 of 80 documents"); the package README and `rag_info` state the same scope, and the self-test searches for words of left-out documents and expects nothing.
- `#mcp-versioning` — the package's version. **A new package** gets a new id at 1.0.0; **New version of …** (`#mcp-base`, from this project's package history) keeps that package's id, bumps the minor version (`#mcp-version` overrides it) and lists the documents added, changed and removed since then (`CHANGES.md` in the package, the Package page). `#mcp-base-upload` reads an exported archive (+ passphrase) as the base when it is not in the history. Every package carries its id, version, date, parent version and document list (name, sha256, size) in `rag_info` / `GET /health`; a running copy updates in place with `bash update.sh NEW.tar.gz` (keeps `rag.config.json` and the keyfile, refuses another package id unless `--force`). CLI: `fts brain export --new-version-of ID` / `--base ARCHIVE` / `--version X.Y.Z`.
- `#mcp-hide-names` — Hide file names in answers (public bot; off by default): the package's answers cite no source files (`[Harrowgate_deal_sheet.xlsx]` would look internal to a customer). The answer model sees passages by number only, any file name it writes anyway is removed, and the package's chat page shows no source list. Your own tools still get the sources by asking: `POST /ask` with `"sources": true`, `rag_answer` with `include_sources`. `/search` is unchanged. CLI: `fts brain export --hide-file-names`; where it runs: `RAG_HIDE_FILE_NAMES=1`.
- `#mcp-originals` — Include original files: the uploaded files themselves ship in the package (encrypted with the corpus). Agents fetch one with the MCP tool `rag_get_document` (embedded file, up to 20 MB inline; larger ones come back as a link), `rag_list_documents` answers "which files do you have about X", browsers download at `GET /files/<id>`, and the package's chat page shows a download link under each source. Anyone with access to the server can download them: leave it off for a public bot. Off by default. CLI: `fts brain export --originals`.

## What to check
The top panel says *Ready*; documents and passages counters after build; the search test returns the correct passage with a source filename. The exported bundle (.ftsrag) and the standalone server package are AES-256-GCM encrypted by default.

## Common mistakes
Changing the embedder without a rebuild; editing a file and not updating (the panel shows *Needs an update*); using the Smart Brain for facts the model should recall with no index attached; using training where citations are required.
