What connects today

  
Local MCP (stdio) and Streamable HTTP at POST /mcp are shipped. Core tools:
    rag_search, rag_info, rag_profile, rag_list_documents.
    rag_get_document depends on included originals; rag_answer depends on answer generation and your LLM connection.

  
New exports provide GET /v1/models, POST /v1/retrieve (passages, scores and optional pictures),
    and POST /v1/chat/completions (knowledge + your operator-configured LLM).
    Choose OpenAI-compatible API above for setup and checks. Text chat supports JSON or buffered SSE;
    no provider gives an honest 503, never a fake answer. Sources are attached in knowledge.sources
    and the answer cites the evidence unless file names are hidden. Client requests cannot change the upstream or package scope.

  
Actions setup and a retrieval-only relay are available above; automatic tunnels and account certification
    are not shipped. The Linux MCPB bridge needs an already installed package and a compatible host;
    Claude Desktop's official macOS/Windows MCPB installation is outside this Linux-only product's scope and is not certified.
    No LLM is included or impersonated.

Download contains config and registration templates. Split them into bot-config.json and the vendor
registration file. Replace all audience IDs: workspace/team (guild for Discord), channel, allowed users and
application ID (tenant ID for Teams). Export a separate scoped package for each audience; there is no automatic

On the package host set RAG_AUTH_TOKEN and the indicated vendor verification secret privately;
Discord uses its public Ed25519 key, not a bot token. Configure the package LLM separately. Run the generated
command in the installed package folder; it binds only loopback. Public HTTPS ingress and vendor registration
must be reviewed and configured separately. Publish ONLY this bridge, never Studio or the full package server.


Slack and Discord acknowledge promptly and deliver private ephemeral replies asynchronously. A restart may
lose pending replies; no automatic retry is attempted, and persistent replay protection blocks duplicates.
Ask a new question after an error. Teams outgoing webhooks reply to the whole configured public channel and
have a short response deadline: a slow/cold LLM yields an honest unavailable reply, not deferred bot delivery.


Questions and scoped passages reach the operator's LLM; answers/sources reach the selected chat vendor.
The package's R8 privacy/retention settings still apply. Bridges do not store question text or vendor tokens;
their replay database stores bounded expiring hashes. Protect it and keep it across restarts. This is not R13
signed identity/audit, a full Azure Bot, a background service manager, or vendor certification.


Account gates: Slack app install and commands permission; Teams team/tenant outgoing-webhook permission;
Discord application command registration/install and interaction URL validation. Test known/no-hit questions,
wrong audience, invalid signatures and shutdown in the vendor account before use.
